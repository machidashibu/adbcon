* Open APIのserverで定義したhost (bind)とportを使用してサーバを起動していた。
* その定義されたポートが別のアプリで使われているときにリビルドしないと起動ができなくなってしまう。

## Options Considered
1. OpenAPIで定義したserverのurlからbindとport取得する。
2. コンフィグファイルからbindとportを指定する。
3. **(Chosen)** コンフィグファイルからbindとportを指定する。その時にbindとportを指定していない場合はOpenAPIで定義したserverのurlからbindとport取得する。
4. コマンドライン引数で指定する。

## Decision
<!--

* **決定理由:** なぜその選択肢を選んだのか？

3番目を選択する
### Rationale:
  * 基本的にはOpenAPIで明示的に定義したものをそのまま使わせたい。
  * 出来れば起動時に実行ファイル以外のファイルを極力用意する必要を除きたい。（常用 or コンフィグ側でのデフォルト
  * なので、今回は例外的な状況の時にリビルドを使わずに変更できる例外的な対応としてコンフィグファイルを使用する。
  * コマンドライン引数はまだ整理できていないので今回位は除外。（使う場合はヘルプの実装が必要なので）

## Consequences
### Positive Impact (Pros):
  * 基本的に新たなファイルなどを用意する（させる）必要がない。
    * 予めコンフィグファイルの作成、指定が必要だと途端に知らない人の利用難易度が上がる。
    * アプリの際は一時の説明が楽。（実行ファイルだけコピーさせればよいので）
  * ユニットテスト用のデータ注入が楽
  * 同じように例外的なことが見つかった場合対処しやすいし、比較的シンプル
    * コマンドライン引数を使う場合はゴチャゴチャしやすい。
### Negative Impact / Trade-offs (Cons):
  * コンフィグファイルの設定方法などの説明を何らかの形で追加する必要がある。
